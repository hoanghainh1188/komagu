## [1.2.1](https://github.com/hoanghainh1188/komainu/compare/v1.2.0...v1.2.1) (2026-10-24)

### 🧠 Two-Tier Architecture & Bring-Your-Own-LLM (BYO-LLM) Model
- **Explicit Architecture Separation**: Formally established the clear distinction between:
  - **Tier 1 (Deterministic Engine)**: 100% offline, local, zero-dependency pre-scan, WAF edge provisioning, AST query rewriting, and cross-user authorization gating via Python 3.8+ stdlib and Node CLI.
  - **Tier 2 (Cognitive AI Multi-Agents)**: Bring-Your-Own-LLM (BYO-LLM) execution via Claude Code, Cursor, Antigravity, OpenHands, or private/on-premise LLM APIs (Ollama, vLLM).
- **Enterprise Data Sovereignty**: Documented compliance with enterprise confidentiality and NDAs—Komainu makes no unauthorized external LLM API calls and avoids hardcoded API keys.
- **Architectural Decision Record**: Published official [ADR-0006](https://github.com/hoanghainh1188/komainu/blob/main/docs/adr/0006-byo-llm-runtime-neutral-architecture.md).

### 🖥️ Interactive CLI & Developer Experience
- **Transparent CLI Guidance**: Updated `komainu scan` and `komainu help scan` to clearly label execution as Tier 1 Deterministic Engine and display next steps for Tier 2 cognitive verification.
- **Actionable Adapter Generator**: `python3 assess/lsa/adapters/build_adapters.py` now prints exact, copy-pasteable next-step invocation prompts when generating Claude Code skills/subagents, Cursor rules, or Generic pipeline contracts.

### 🧪 Verification & Release
- Verified 100% pass across all test suites (`assess/lsa/tests/run_tests.py`, `operate/tests/test_cli.py`, and `npm test`).
- Published packages:
  - `komainu-guard@1.2.1` on npmjs
  - `ghcr.io/hoanghainh1188/komainu:v1.2.1` on GHCR

## [1.2.0](https://github.com/hoanghainh1188/komainu/compare/v1.1.0...v1.2.0) (2026-10-21)

### 🚀 New Capabilities

- **Automated CVE Dependency Remediation (`komainu fix --sca`)**:
  - Automatically identifies and rewrites vulnerable dependencies across 5 major software ecosystems and 7 manifest formats:
    - **Node.js / JavaScript / TypeScript**: `package.json` (`dependencies`, `devDependencies`, `peerDependencies`, `optionalDependencies`)
    - **Python**: `requirements.txt`, `Pipfile`, `pyproject.toml`
    - **Go**: `go.mod`
    - **.NET / C#**: `.csproj` (`<PackageReference>`)
    - **Java / Kotlin**: `build.gradle` & `build.gradle.kts`
- **Companion Lockfile Synchronization (`--sync-lockfiles`)**:
  - Synchronizes companion lockfiles in-place whenever manifests are updated:
    - `package-lock.json` (v1, v2, v3 formats, including root dependencies and `packages` trees)
    - `yarn.lock`
    - `Pipfile.lock`
    - `poetry.lock`
    - `packages.lock.json` (.NET NuGet)
    - `gradle.lockfile`
    - `go.sum`
- **Constraint-Preserving Pinning**:
  - Preserves version prefixes (`^`, `~`, `==`, `>=`, `~=`, `v`) and pins the safe minimum patched release without breaking legacy project configurations.
  - Supports multi-major version boundaries in advisory catalog (e.g. `semver` 6.x vs 7.x backports for `CVE-2022-25883`).
- **Dual-Mode Advisory Sourcing**:
  - Embedded offline `CVEAdvisoryCatalog` (pure Python 3.8+ standard library, runtime-neutral).
  - Live vulnerability intelligence query via `--osv` flag against OSV.dev API.
  - Native integration with `komainu devsecops run` emitting standard SARIF `CWE-1395` findings.

### 🧪 Quality & Verification

- Added `operate/tests/test_dependency_remediation.py` with 12 end-to-end unit tests covering all 7 manifests, 7 lockfiles, CLI options, and dry-run preview diffs.
- 100% passing test suite across all 6 CI workflow matrices (.NET 8, Spring Boot 3, Python 3.8/3.11/3.12, Node.js 20, Go 1.22).

## [1.1.0](https://github.com/hoanghainh1188/komainu/compare/v1.0.1...v1.1.0) (2026-10-21)

### 🚀 New Capabilities
- **Automated Remediation CLI (`komainu fix`):** Dry-run previews, unified `.patch` generation, and in-place code fixes for BOLA (`@RequireOwnership`) and SQL injection findings (#186–#188, #191–#193).
- **LSA Engine Speed & Enterprise SARIF:** Parallel worker pool for route/injection scanning (#196), SHA-256 content-hash scan caching (#197), enterprise SARIF 2.1.0 exporter (#202), and large-codebase benchmark suite (#203).
- **Zero-PII eKYC & OIDC Bridge (Boilerplate 2):** Blind-index tokenization bridge with OIDC identity and J-LIS CA/CRL verification engine compliant with Japan's April 2027 Criminal Proceeds Act amendment (#189, #190, #194, #195).

### 🛡️ Comprehensive Security Hardening
- **Boilerplate 1 (D1 Authz & D2 Identity across 5 Runtimes):** Unified claim semantics (`sub`/`uid`/`userId`/`user_id`/`id` and `tenant_id`/`tid`/`tenant`/`org_id`/`organization_id`), server-side ID binding before trusting request bodies, and strict OIDC `exp`/`nbf`/clock-skew/decoder validation across **.NET 8**, **Spring Boot 3 (Kotlin)**, **Go**, **Node.js (NestJS/Express)**, and **Python (FastAPI)** (#154, #155, #171, #172, #206, #207, #218, #219, #222, #223, #225, #231).
- **Boilerplate 2 (Zero-PII eKYC):** Fail-closed JPKI/SOD certificate verification, strict raw-image rejection, and replay-resistant nonce rate limiting (#159, #213, #214).
- **Boilerplate 3 (Multi-Region Resilience & WORM Backup):** Hardened Terraform S3 Object Lock (`COMPLIANCE` mode), KMS CMK deny-delete policy, and automated DR verification CLI (#176, #210, #226).
- **Boilerplate 4 (Multi-Tenant Isolation & BYOK):** PostgreSQL RLS & schema-per-tenant isolation (`REVOKE ALL FROM PUBLIC`, safe `search_path` switching), AES-256-GCM BYOK envelope encryption with permanent crypto-shredding, and HMAC-SHA256 tamper-evident audit trail (#156, #163, #209, #220, #224).
- **Edge WAF & Remediator Safety:** Coraza WAF CRS v4 & Kong Gateway hardening without audit log token leakage (#175, #211, #212, #227); remediator path containment and encoding preservation (#208, #215, #217).

### 🔒 Continuous Security Scanning CI & Documentation
- Added 6-job `Security Scan` workflow (`.github/workflows/security-scan.yml`) running Bandit, `pip-audit`, `golangci-lint`, `govulncheck`, Roslyn analyzers, Detekt + `StringBuiltSqlQuery`, CodeQL, and Trivy (#232).
- Aligned `README.md`, Sales Pitch Deck, and Modernization Boilerplates Proposal with all 5 Boilerplates (#233).
